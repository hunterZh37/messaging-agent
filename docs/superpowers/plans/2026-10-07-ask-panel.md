# Ask panel redesign implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Celeste's answers list what she leaned on as ranked cards carrying a relevance score that explains itself, in a bigger panel opened from a launcher that floats at the bottom right.

**Architecture:** The score is assembled from four nameable parts — how well the words matched, how close the meaning was, whether both halves found it, and how recent it is — because the same four parts are what the hover reads out. Both halves of the search already compute the first two and throw them away; this keeps them. A citation grows optional fields carrying the card, left optional because Celeste also cites messages that no search ever ranked.

**Tech Stack:** TypeScript, SQLite FTS5 (`bm25()`), `sqlite-vec` (`distance`), Next.js 16 App Router, React 19, vitest.

**Spec:** `docs/superpowers/specs/2026-10-07-ask-panel-design.md`

## Global Constraints

- The score must be explainable: every part of the number is nameable in the hover's sentence. No weight exists that the sentence cannot account for.
- A citation that was never ranked (`get_thread`, `list_mail`, the open thread) renders the card **without** the score rail. Never invent a score.
- Turns stored before this ships have citations with only `messageId`, `threadId`, `subject`, `from`. They must keep rendering — the simple row is correct for them.
- Only **Explain** spends money, and only on a click. Nothing in the card's default state calls a model.
- No real person's name, email address or phone number in any tracked file (`packages/core/test/no-real-people.test.ts`). Tests use `example.com`.
- Never touch the live server on 127.0.0.1:3100, `~/celeste-server`, or the real database at `~/messaging-agent`.
- Comments are prose giving the operator-facing reason, dated `2026-10-07`, matching each file's density.
- `pnpm typecheck` and `pnpm vitest run` pass in both `packages/core` and `apps/web`; `pnpm build` passes in `apps/web`.
- Baseline at the time of writing: core 1316 tests, web 501 tests.

## Review Focus

1. **A citation with no score** — every `get_thread` and `list_mail` citation. The card renders without the rail and without a hover, and nothing throws. (Task 3 and Task 4 tests.)
2. **A turn from before this ships** — `citations` in the database carry four fields and no more. The panel renders them as it does today. (Task 4 test.)
3. **A message with no vector yet** — the normal state during the backfill. Only the words half contributed, so the score must be computed from one part and the sentence must name only that part, not an absent one. (Task 1 test.)
4. **Phone width** — a 620px panel cannot float on a 390px screen. It covers, as the current panel does. (Task 7 test.)
5. **Explain failing** — no network, a model error, a message that has since been deleted. The free text stays on screen and the failure is said once. (Task 6 test.)

```ts
/**
 * How relevant a hit is, as a number the operator can argue with (spec:
 * 2026-10-07, "when I hover over the relevance score, it shows why the search
 * results are what I'm asking for").
 *
 * The constraint that shapes this: the hover explains the score, so every part
 * of the number has to be nameable in a sentence. That rules out a fitted
 * blend of weights — nobody can read one of those out loud. So it is four
 * things, each of which `explainScore` below can say.
 *
 * The weights are a stated guess. They cannot be measured until the scores can
 * be seen against real questions, which is what this builds; expect them to
 * move once the operator has looked at a week of them.
 */
export interface ScoreParts {
  /** `bm25()` from the keyword index: negative, and more negative is better. Absent when the words half did not find it. */
  words?: number;
  /** Cosine distance from the vector table: 0 is identical. Absent when the meaning half did not find it. */
  meaning?: number;
  /** How long ago it was sent. */
  ageMs: number;
  /** Whether any of the operator's words are in the subject, which is worth saying out loud. */
  inSubject: boolean;
}

/** A bm25 at or beyond this counts as a full-strength word match. Measured: the best hit for a common term sits near -9. */
const WORDS_FULL = 12;
/** A cosine distance at or beyond this counts as no meaning match at all. */
const MEANING_FAR = 1;
/** What two independent kinds of evidence agreeing is worth. */
const BOTH_BONUS = 0.15;
/** The most recency can add. A nudge: it must never carry a weak match past a strong one. */
const RECENCY_NUDGE = 0.05;
/** Recency has faded to nothing by here. */
const RECENCY_SPAN_MS = 90 * 86_400_000;

function clamp01(n: number): number {
  return Math.min(1, Math.max(0, n));
}

/** The words half's contribution, 0 to 1. */
function wordsPart(bm25: number | undefined): number | undefined {
  if (bm25 === undefined) return undefined;
  // bm25 is negative and better the lower it goes; flip it so bigger is better.
  return clamp01(-bm25 / WORDS_FULL);
}

/** The meaning half's contribution, 0 to 1. */
function meaningPart(distance: number | undefined): number | undefined {
  if (distance === undefined) return undefined;
  return clamp01(1 - distance / MEANING_FAR);
}

export function relevanceScore(parts: ScoreParts): number {
  const w = wordsPart(parts.words);
  const m = meaningPart(parts.meaning);
  // The better half leads. A message both halves found then takes a bonus on
  // top, because two kinds of evidence agreeing is the strongest thing this
  // system knows — not the average of them, which would punish a message that
  // one half was merely lukewarm about.
  const best = Math.max(w ?? 0, m ?? 0);
  const both = w !== undefined && m !== undefined ? BOTH_BONUS : 0;
  const fresh = RECENCY_NUDGE * clamp01(1 - parts.ageMs / RECENCY_SPAN_MS);
  return Math.round(100 * clamp01(best + both + fresh));
}

/** "3 days ago", or "today" for anything inside a day. */
function age(ageMs: number): string {
  const days = Math.floor(ageMs / 86_400_000);
  if (days < 1) return "today";
  if (days === 1) return "yesterday";
  if (days < 60) return `${days} days ago`;
  const months = Math.round(days / 30);
  return `${months} months ago`;
}

/**
 * Why this message scored what it did, in the operator's own terms. Names only
 * the parts that actually contributed: during the backfill most mail has no
 * vector, and a sentence claiming a meaning match where there was none would
 * be worse than no sentence at all.
 */
export function explainScore(parts: ScoreParts, terms: string[]): string {
  const said: string[] = [];
  const quoted = terms.length > 0 ? `“${terms.join(" ")}”` : "your words";
  if (parts.words !== undefined && parts.meaning !== undefined) {
    said.push(`Found both ways: ${quoted} appear in it${parts.inSubject ? ", in the subject" : ""}, and it is close in meaning to what you asked`);
  } else if (parts.words !== undefined) {
    said.push(`Matched ${quoted}${parts.inSubject ? " in the subject" : ""}`);
  } else if (parts.meaning !== undefined) {
    said.push(`Close in meaning to what you asked, though ${quoted} are not in it`);
  } else {
    said.push("Cited from the thread you had open, not from a search");
  }
  said.push(`sent ${age(parts.ageMs)}`);
  return `${said.join("; ")}.`;
}
```

```ts
/** Below this a score greys out: in a list where everything looks confident, nothing does. */
const STRONG_FROM = 70;

export function scoreTone(score: number): "strong" | "weak" {
  return score >= STRONG_FROM ? "strong" : "weak";
}

/**
 * The line under a card's subject: who it is from, where it is filed, when it
 * arrived — whichever of those the citation actually carries. A turn stored
 * before cards existed carries only the sender, and says only that.
 */
export function cardMeta(c: Citation): string {
  const sender = c.from.replace(/\s*<[^>]*>\s*$/, "").trim() || c.from;
  const when = c.sentAt === undefined ? null : new Date(c.sentAt).toLocaleDateString(undefined, { day: "numeric", month: "short" });
  return [sender, when].filter(Boolean).join(" · ");
}
```

```ts
/**
 * What the popover says. The free text from the ranking is always there; what
 * Celeste said replaces it only once it is actually back, and a failure leaves
 * the free text standing rather than blanking the panel (spec 2026-10-07).
 */
export function explainState(input: { free: string; asked: { sentence: string } | { error: string } | null }): {
  text: string;
  source: "ranking" | "celeste";
  failed?: string;
} {
  if (input.asked && "sentence" in input.asked) return { text: input.asked.sentence, source: "celeste" };
  if (input.asked) return { text: input.free, source: "ranking", failed: input.asked.error };
  return { text: input.free, source: "ranking" };
}
```
